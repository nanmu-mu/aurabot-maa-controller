# 首发功能规格

## 使用场景

主人在 QQ 私聊明确请求执行一次日常，Aurabot 调用本模块运行本机 MAA 的固定预设。已在执行时返回现有状态，不启动第二份。任务实际开始和结束后返回原始授权会话。

## 固定首发范围

- Windows x64，Aurabot API v1，独立 MaaCore 执行器。
- MAA 6.21.3 的已核验版本、资源指纹与参数；官服、MiniTouch、MuMu实例0、127.0.0.1:16384。
- StartUp → Recruit → Infrast → Fight → Mall → Award，作战固定1-7、六连战、不补药/源石。
- 受控配置转换；主人后续修改GUI需显式同步，不自动迁移账号或统计身份。
- 主人私聊授权、单次票据、重复启动保护、GUI单次关闭许可、真实状态/统计查询、温和停止和完整强制终止。
- 宿主对象重载、QQ暂时断线及已验收宿主完整退出后，继续同一任务并核对结果。

## 资源与权限

禁止消耗至纯源石、合成玉、寻访凭证、理智药剂或加急券；允许固定预设内信用购物、招聘许可和已确认的基建原料使用。参数检查不等于对游戏图像识别结果提供资产冻结保证。

只有可靠主人原始QQ私聊可以发起执行；群聊、陌生人、转发、引用、模拟消息及不可信文本不得授权。本地执行不接受任意系统命令、动态任务、聊天指定路径或进程。

## 结果语义

- 完成：固定队列按既定策略结束，有足够任务链和idle证据。
- 部分完成：部分步骤有成功证据，同时存在已知任务失败。
- 失败：明确执行失败；不自动重跑。
- 取消：主人停止请求得到实际停止/终止结果。
- 未知：证据不足、执行器异常退出或未确认安全释放，明确说明并阻止盲目重复启动。

只有 API 受理、进程创建、开始返回值或进程退出，都不足以独立证明日常完成。

已核验条件节点的检测未命中单独记录，不等同任务失败；未知子步骤错误仍明确报告节点，任务链失败仍按部分完成或失败处理。优先购物目标全部售罄时，只有固定队列已完成且原生日志可确认同一步骤的全部售罄证据，才显示正常跳过。证据不足时继续告警，保留原生错误代码和诊断。

正常完成保留模拟器。完成后可由主人新的明确单次请求关闭绑定实例；清理成功或失败单独记录，不覆盖原任务结果、完成时间、统计及已有告警，不重发已确认送达的最终通知。归属不明、任务已被更新或设备/MAA互斥占用时拒绝清理。

## 非目标

不提供每日定时、自主游戏规划、其他游戏支持、任意关卡/模拟器/服务器、断点续跑、自动重试、公共ADB重启、账号登录自动化或付费购买。
