# Aurabot MAA Controller

**0.1.7 · 预发布候选 · Windows · AGPL-3.0-only**

通过主人 QQ 私聊，让 Aurabot 执行一份预先配置的本机 MAA 日常，并依据真实状态汇报开始、进度和结果。

这是独立的 Aurabot API v1 用户模块，使用独立 Python 执行器加载用户本机的 MaaCore。不重新实现游戏自动化，不需要手动点击 MAA 的开始按钮。

## 当前支持范围

首发范围刻意保持固定；这不是适配任意模拟器、服务器或任务组合的通用控制器。

- Windows x64；已验收宿主为 DSH Desktop 0.2.1-rc.5、Aurabot 1.1.24 / API v1。
- MAA 6.21.3，运行时同时检查版本及 DLL/资源定义指纹；其他版本拒绝执行。
- MuMu 实例 **0**，ADB 端点 **127.0.0.1:16384**，`MuMuEmulator12` 连接配置、MiniTouch，关闭 AdbLite。
- 明日方舟官服；六项固定顺序：唤醒 → 公招 → 基建 → 1-7 作战 → 信用收支 → 领取每日/每周任务奖励。
- 主人明确发起一次任务；没有每日定时、自主触发、动态关卡、断点续跑或失败后自动重跑。
- Node.js 声明要求 >=22，已测试 24.19.0；Python 已测试 3.14.4。代码使用标准库，无 npm/pip 第三方运行依赖。

其他 Aurabot、MAA、MuMu 或 Python 版本没有因此自动获得兼容保证。版本升级后应先核验，不能只重新生成指纹来绕过检查。

## 功能与权限

- 仅可靠识别的主人原始 QQ 私聊可以生成一次性请求。群聊、陌生人、转发、引用、模拟面板消息及不可信文本不能授权本地执行。
- 只执行白名单 MAA 操作，聊天内容不会拼成系统命令。
- 单任务锁和持久账本避免重复启动；既有 GUI 阻塞时，每次单独请求五分钟有效的关闭许可。
- 温和停止等待 MaaCore 停止队列，保留模拟器；强制终止结束本次执行器并关闭绑定实例 0，也适用于主人手动打开的该实例。
- 不终止其他实例或共享 ADB 服务，不自动重启公共 ADB、切换实例、重启模拟器或重跑任务。
- 不消耗至纯源石、合成玉、寻访凭证、理智药剂或加急券；固定预设允许信用购物、招聘许可和已确认的基建生产原料使用。
- 不向企鹅物流或一图流上报，QQ 汇总来自本次本地回调。只列可靠识别的统计，不虚构进度百分比或完整资产账单。

“预设完成”表示固定队列按既定策略结束，不代表游戏内所有日常目标全部达成。结果区分完成、部分完成、失败、取消和未知。

## 安装

先阅读 [安装与配置](docs/INSTALL.md)。Releases 应同时提供：

- `aurabot-maa-controller-0.1.7.zip`：Aurabot 模块安装包；
- `aurabot-maa-controller-0.1.7-source.zip`：同版本完整源码与构建脚本；
- `SHA256SUMS.txt`：文件校验值。

模块默认停用，示例配置默认 `mode=mock`、`realEnabled=false`。安装不会自动开始真实任务。首次接入应先检查本机路径、主人身份、绑定实例、预设和消费限制，再明确启用真实模式。

MAA、MuMu、Node.js、Python、Aurabot、QQ 网关和游戏均需自行安装；安装包不携带这些软件的二进制或游戏资源。

## QQ 使用示例

- 开始：`帮我把明日方舟日常清一下`
- 查询：`这次日常现在什么进度了？`
- 温和停止：`停止本次日常`
- 强制终止并关闭实例 0：`强制终止本次日常`

遇到既有 MAA GUI 时，可以在同一主人私聊普通发送 `同意，关闭当前这个 MAA 并开始日常。` 或 `不允许关闭 MAA`。不要引用旧消息；关闭许可只适用于本次进程和本次预设。

收到“已受理”不代表任务已开始；开始通知依赖实际任务回调。失败或未知后，先检查结果，再由主人明确决定是否重新发起。

## 验证与限制

0.1.7 的 36 项 Node、20 项 Python 离线测试已通过。真实验收覆盖主人 QQ 启动、重复保护、GUI 许可/拒绝、进度查询、温和停止、QQ 短暂断线、DSH 完整退出恢复以及完整强制终止。

完整日常自然结束的既有通过基线是 MAA 6.21.1；6.21.3 已完成接口、资源、参数核验和上述真实控制实测，尚未重新跑完整套自然结束。长时间离线后最终通知补发，以及其他实例并行运行时的隔离，没有单独做真实验收；相关逻辑有离线覆盖。详见 [验证记录](docs/VALIDATION.md)。

任务运行时不要更新 MAA，或让其他 MAA 安装/自动化工具操作同一模拟器。图像识别自动化的参数限制不能当作游戏资产冻结保证。

## 开发

在源码根目录执行，仅使用模拟任务：

```powershell
py -3.14 -m venv .venv
npm test
.\.venv\Scripts\python.exe -B -m unittest discover -s test -p 'test_*.py'
node scripts/demo.mjs
node scripts/package.mjs
```

测试不连接真实游戏、QQ 或生产模块；只终止测试自行创建的模拟执行器。开发约定见 [CONTRIBUTING.md](CONTRIBUTING.md)，接入设计见 [docs/INTEGRATION.md](docs/INTEGRATION.md)。
